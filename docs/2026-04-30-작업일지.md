# 2026-04-30 작업일지

## 작업 목적

국내 주식 후보 분석 시스템을 로컬 웹앱 형태로 개선하고, 검색한 종목을 즉시 Kiwoom 데이터로 적재한 뒤 현재 점수 로직으로 평가할 수 있도록 확장했다.

## 현재 프로젝트 구조

- Backend: FastAPI
- Frontend: Next.js
- Database: PostgreSQL
- Backend port: `8000`
- Frontend port: `3000`
- 접속 주소: `http://127.0.0.1:3000`
- Next.js 위치: `frontend/`
- 재기동 파일: `restart-dev.cmd`
- 바탕화면 재기동 파일: `auto-project 재기동.cmd`

## 주요 완료 작업

### 1. 검색 종목 즉시 적재 및 점수 계산

기존 검색은 `daily_candidate_scores`에 이미 저장된 종목만 조회할 수 있었다. 오늘 작업으로 검색 결과가 없을 때 Kiwoom 일봉 데이터를 즉시 요청하고, DB에 적재한 뒤 기존 점수 로직으로 평가하는 흐름을 추가했다.

추가/수정 파일:

- `app/on_demand_scoring.py`
- `app/main.py`
- `app/postgres_repository.py`
- `frontend/app/page.tsx`

API 흐름:

```text
GET /api/stocks/search?date=YYYY-MM-DD&q=검색어&autoLoad=true
```

동작:

1. 검색어가 종목코드면 6자리 코드로 정규화
2. 검색어가 종목명이면 `stock_master`와 수동 별칭 파일에서 코드 조회
3. Kiwoom REST API로 일봉 데이터 요청
4. `daily_prices` 적재
5. `evaluate_daily_batch`로 점수 계산
6. `daily_candidate_scores` 저장
7. 검색 결과로 점수, 현재가, 목표가, 손절 참고가, 리스크 반환

검증된 예:

- `034220` 검색/적재/점수 계산 성공
- `에코프로비엠` 검색/적재/점수 계산 성공

- 다음 기준 후보:

```text
코스피 종가가 20일선 아래로 이탈
20일선 기울기가 하락 전환
5일선이 20일선 아래로 내려감
코스피 5거래일 수익률이 -3% 이하
전저점 이탈 여부
하락 전환 확정 후 검색 화면 상단에 시장 레짐 표시
```

- 현재 작업 중단 시점 기준으로 지수 하락추세 레짐 구현은 완료 처리하지 않음.

### 3. 후보 없는 날짜 조회 개선

30일처럼 매수 추천 기준을 넘는 종목이 없는 날에도 화면 조회와 지수 추세 표시가 가능하도록 수정.

기존:

```text
/api/candidates/daily?date=2026-04-30 -> 404
```

변경 후:

```text
/api/candidates/daily?date=2026-04-30 -> 200
candidates: []
emptyReason: 적정 점수 이상 종목이 없습니다.
```

프론트 표시:

- 후보가 없으면 `적정 점수 이상 종목이 없습니다.` 노출.
- 후보가 없어도 그날의 지수 추세는 계속 표시.
- 초기 기준일은 `latestTradeDate`를 우선 사용.

### 4. 고점수 추적 통계 기준일 수정

고점수 추적 페이지가 `latestScoreDate` 기준으로 묶여 있어, 다음 거래일 가격이 들어와도 수익률이 갱신되지 않는 문제 수정.

문제 예:

```text

latestTradeDate: 2026-04-30

SK이노베이션 2026-04-30 종가: 146200
화면 수익률: 0.00%
```

수정 후:

```text
asOf: 2026-04-30
096770 SK이노베이션
기준가: 149800
현재가: 146200
등락: -2.40%
```

변경 파일:

- `app/main.py`
- `tests/test_app_endpoints.py`

### 5. 날짜 선택 유지 버그 수정

검색 화면 달력에서 2026-04-29를 선택하면 다시 2026-04-30으로 돌아가는 문제 수정.

원인:

- 초기 로딩 `useEffect`가 `loadBoard` 변경에 반응해 다시 실행됨.
- 그 과정에서 날짜가 `latestTradeDate`로 재설정됨.

수정:

- 초기 로딩은 한 번만 실행되도록 `initialLoadDoneRef` 추가.
- 날짜 변경 시 직접 중복 조회하지 않고 `selectedDate` 변경 후 기존 디바운스 조회만 타도록 정리.
- 요청이 겹칠 때 오래된 응답이 화면을 덮지 않도록 request id 보호 추가.
- 결과 목록은 프론트에서도 점수 내림차순으로 재정렬.

변경 파일:

- `frontend/app/page.tsx`
